# ファイル弾幕 開発用のテストと計算

MOD 本体は `file-danmaku/mod/`。配る zip に入れたくないので、テストは本体に置かず、ここにまとめる。
`unit.mjs` `parts.mjs` `game.mjs` `play.mjs` は `node` だけで動く。`browser.mjs` は、Edge（なければ Chrome）が入っていれば動く。MOD のファイルは、実行のたびに一時フォルダへコピーして読む（`stage.mjs`）。

## play.mjs の見方
- 面ごとに「クリア 秒数 ライフ 被弾 かすり 与ダメ 弱点に当てたダメ 砲の数 スコア 素材」が出る。ゲームオーバーなら、そこで止まる。最後に、弱点に当てた割合も出る。
- `--hand`：持っているファイル。`mixed` はいろいろ 40 個、`beams` は動画ばかり（ファイブカード）、`small` は小さいファイルばかり（豆の群れ）、`big` は大きいファイルばかり、`none` は空。
- `--progress`：面をクリアするごとに素材をもらい、強化と役の解放を買っていく（遊びつづけた人の育ちかた）。`--cap` `--meta` `--unlock` は、はじめから育った状態で始める。
- `--human`：人にちかづける（見るのがおそく、動きがぶれる）。**難しさの目安は、これで見る**（ふつうの難しさ・育ちかた込みで 7〜14 面でやられるのが ねらい）。何もつけないボットは、人より かなり強い。
- ボットは、砲が溜まったらすぐ放す。放さずに溜めたままにすると、ふつうの弾が撃てないままになる（人間も同じ）。
- `--from=6` で、機械的に作ったボスを通せる。
- 数字（体力・弾の数と速さ・素材の量）を変えたら、`--human --progress --stages=10` で、傾きが大きく変わっていないかを見る。

## 難しさのつりあい（フォルダのボス）
- `play.mjs --folder=8:beam --human --meta=4 --cap=4` のように、格と本性の種類を決めて 1 体と戦う（`:root` を足すと ドライブの根）。同じ格の ふつうの面（`--from=8 --stages=1`）と くらべて、被弾の数が 大きく変わらなければ 釣り合っている。
- 格の天井は 8（面の 8 と同じ強さ）。TB のドライブも 同じ。大きいフォルダは フェーズが多い（格 5 から 4）ぶん 長い。

## browser.mjs のシナリオ
- `basic`：武器庫の 5 つの画面（ファイル・図鑑・役の一覧・整備場・操作設定）→ 出撃 → 一人称 → 三人称
- `puzzle`：盤の操作（持ち上げる・緑と赤の予告・回す・置く・取る・Esc でもどす・ダブルクリックで自動・おまかせ詰め）と 整備場の購入・役の解放（`--rich` で素材つき）
- `folder`：フォルダのボス（挑めるフォルダをさがす・到達 1 / 2 / 3 で 一覧が変わる・掘る深さ・挑めるものの中は省く・まだ早いものは予告だけ・選んで挑む・制覇して覚える・倒しなおしは 35%・やめる・ドライブの根は数えず ラスボスの予告・到達 8 で挑める）。`--reached=N` で 到達を決めて始められる
- `reset`：進行度の初期化コマンド（やめる・初期化・保存も消える・キー設定は残る・戦いの最中でも）
- `files`：ファイルのタブ（グリッド・名前や大きさが マスに出ないこと・触れると詳細・6 種類の並べかた・種類と段と名前のしぼりこみ・入力中に入力欄が作りなおされないこと・下の階層もさがす：条件がないと 20MB 以上、小さいものも探せる、種類は拡張子で渡す・おまかせ詰めは 見えているものだけ）
- `threat`：真上・真下から来る弾と、雨の印に 合図が出ること（`--practice`）
- `keys`：操作設定（割り当てを変える・かぶったら外れる・Delete で外す・マウスのボタンを割り当てる・もとにもどす・保存）と、変えたキーで進めること
- `fp`：一人称の操作（マウスで見る向きが変わる・ボスのほうを向く・左ボタンでショット・右ボタンで溜め・ホイールで種類・Space と C で上下・V で三人称・固定が外れると中断・つづけると固定）。`--nolock` で、固定できない環境のふりをしても 遊べること
- `cannons`：8 種類の砲を、練習モードで 1 つずつ撃つ（`--practice --cap=8 --unlock` が よい）
- `roman`：10GB をこえる砲（超ロマン砲）を撃つ
- `flow`：大物をさがす・フォルダへ入る・中断・面クリア→素材→次の面・ゲームオーバー→もういちど（画面のつながり）
- `altitude`：Space で上がる・C で下がる。弱点の高度計と、弾の高さを見る
- `phases`：フェーズごとの弾幕（`--stage=2 --phases=3 --wait=9000`）
- 中のゲームは、URL に `?debug` を付けて読んだときだけ `window.__fd()` で覗ける（`browser.mjs` が使う）。
- ヘッドレスの Edge は、終わったときに 子プロセスごと閉じる（Windows では、起動したプロセスだけを止めても、描画の子プロセスが残って CPU を使いつづける。このハーネスは 一時プロファイルの名前で探して止める）。重くなったら `fd-edge-` を含む msedge が残っていないかを見る。

## 確かめられないこと
- 本物の explorer_plus の中での動き。偽の本体と、偽のポインターロックで代用している。
- 手触り（一人称の照準・視点の回り方・マウスの感度・キー配置の使いやすさ、避けやすさ、溜めの重さ）、音、本物の GPU での速さ。ヘッドレスは、ソフトウェア描画なので遅い。
